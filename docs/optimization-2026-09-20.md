# 编辑性能、体积与界面优化

本次比较以 `99813fb` 为基线。保留双向同步、键值菜单、撤销重做、空白创建 URL、分栏记忆及二维码功能，不增加运行时依赖。

## 实现

- 同步另一侧时只替换变化的文本，保留未变化区域的排版和临时属性。
- JSON 仍完整检查语法，但只更新受影响的上色区间；复用颜色对象。
- TextKit 1 开启非连续布局，按需计算文本位置。测试覆盖 1000 行文档滚动到末尾再回到开头，以及增量配色与完整配色逐字符一致。
- 工具栏使用无边框原生按钮和系统符号，编辑区使用细边框；协议、Host、路径移到顶部。没有新增图片、阴影、动画或 UI 框架。
- 发布构建使用 `-Osize`，移除非必要符号；图标保留 16–512 实际像素资源，去除重复的 512 像素条目和 1024 像素条目。原始图标文件仍保留在 assets 中。

## 编辑耗时

同一台 Apple Silicon Mac，1000 个参数，三轮交替运行优化前后程序。每个场景连续编辑 30 次，计入同步、上色、撤销记录和可见区域绘制。优化前采用原构建参数 `-O`，优化后采用最终参数 `-Osize`。探针只进入临时构建，不进入正式应用。

下表取三轮平均耗时的中位数，单位毫秒：

| 场景 | 优化前 | 优化后 | 减少 |
| --- | ---: | ---: | ---: |
| 左侧 URL 编辑 | 17.27 | 15.32 | 11.3% |
| 右侧 JSON 编辑 | 12.04 | 10.76 | 10.6% |

[完整记录，包括各轮 P95](performance-2026-09-20.txt)。系统负载有波动，其中一轮 URL 编辑优化后反而较慢；这些结果不代表所有输入都能获得固定比例的提升，也不保证每次编辑都低于 16 毫秒。超长文档仍有完整解析和格式化开销。

复测：`./scripts/measure-performance.sh`。需要在图形桌面会话中运行，会打开独立的临时测量窗口并自动退出。两侧操作均使用实际文本组件，避免仅测解析器而漏掉界面开销。

## 应用体积与内存

同为 arm64 + x86_64 通用应用，按包内文件的逻辑字节数合计：

- 优化前：1,996,740 字节，约 1.90 MiB。
- 优化后：773,650 字节，约 0.74 MiB，减少 61.3%。
- 新图标资源：354,027 字节。图标在常规 Dock 和 Finder 尺寸下保留 Retina 资源；大于 512 像素的显示会缩放。

同一内存脚本分别测量一次，`phys_footprint`：空白约 32.3 → 34.0 MiB，1000 参数约 47.0 → 47.8 MiB，连续编辑后约 47.8 → 48.5 MiB。内存没有明显下降；本次主要改善编辑路径和安装体积，不把包体缩小当作内存收益。

[优化前内存记录](memory-flat-before.txt) · [优化后内存记录](memory-flat-after.txt)。内存探针使用 Release 默认优化参数，与此前内存脚本一致；单次采样不构成内存上限或精确的回归结论。

26 项自动化测试通过。包含有效与无效 JSON、同长度替换、中文及 emoji、增量与完整配色比对、长文档滚动、上下文菜单、组件编辑和撤销重做。两个架构完成构建，应用签名验证通过。原生窗口已检查工具栏、组件输入和 JSON 显示。
